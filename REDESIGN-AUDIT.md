# REDESIGN-AUDIT — decisiontune-ai eval report (2026-10-13)

Web-facing surface: `decisiontune eval --html-out report.html` (generated by
`decisiontune/report.py::to_html`). The product is a CLI; the HTML report is
the artifact users share, so it must read like output from a real ML platform.

Competitors researched (ML experiment / eval reporting):
1. **Weights & Biases** — run-comparison view: color-coded runs, metric cards
   with deltas, overlay charts, interactive sidebar toggles, metadata diff
   highlighting, verdict-style summaries ("run A beats run B on X").
2. **MLflow** — experiment comparison table (best value highlighted),
   parallel-coordinates comparison, run detail with params/metrics/artifacts
   tabs, model registry.
3. **Hugging Face** — leaderboard-style tables with rank movement, yellow/black
   brand, tabbed metric views, dataset cards with metadata headers.

## Visual gaps (current vs. competitors)
1. **No verdict.** The reader must mentally compute whether the tuned model
   won. W&B/MLflow lead with the comparison outcome.
2. **No experiment header.** A plain "decisiontune / eval report" title and one
   meta line. Real tools show a run header: models, dataset, sample counts,
   timestamp — the provenance block.
3. **Metric cards lack delta context.** Three isolated cards (tuned acc,
   baseline acc, agreement) with thin bars; no delta chips, no CI.
4. **No calibration visualization.** ECE/Brier are the point of a decision
   model; they're rows in a table instead of a visual comparison.
5. **Per-question-type is a bare table.** MLflow/W&B show grouped bars.
6. **Generic teal-on-gray document styling** — reads as a static doc, not an
   experiment console.
7. **No rounded corners** (good — already compliant), but also no distinctive
   identity: could be any tool's output.

## Functional / flow gaps
1. Only the top-5 regressions are shown; fixed questions aren't listed at
   all — the "what did tuning actually change" story is half-told.
2. No per-question delta table (W&B's sample-level comparison equivalent).
3. Bootstrap CI is a text fragment, not visualized.
4. Errors (if any) have no section.
5. No methodology note (how accuracy/ECE/Brier/agreement are computed) —
   MLflow documents metric semantics next to the numbers.

## In scope for this redesign
1. Ink-black experiment header band: report title, model names, dataset meta
   (examples/questions), timestamp. HF-style amber accent on ink.
2. Verdict banner: tuned beats / does not beat baseline, with accuracy delta
   and the paired bootstrap 95% CI.
3. KPI cards with delta chips: tuned accuracy, accuracy delta (CI), agreement,
   ECE (tuned vs baseline), Brier.
4. Head-to-head table with inline delta bars (keep `<table>`, keep
   "decisiontune", "What changed", "Regressions" strings for tests; keep zero
   `border-radius`).
5. Calibration panel: side-by-side ECE bars for both models + one-line
   interpretation.
6. Per-question-type grouped CSS bars + table.
7. Full per-question delta table (capped at 50 rows) with verdict pills
   (fixed / regressed / still right / still wrong); regressions section kept.
8. Errors section when present; methodology footer.

## Out of scope
- Text and Markdown renderers (unchanged).
- Interactive JS charts (report must stay a single self-contained static
  HTML file — no CDN, no JS dependency; pure CSS bars).
- The CLI, server, and training flows (unchanged).

## Regression contract

  "Regressions" present, no "border-radius" anywhere.
